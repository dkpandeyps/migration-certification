# /generate-pdf-report — Certification Report Generation

> **Path resolution:** relative paths in this skill (`shared/...`, `<skill-name>/references/...`, `<skill-name>/templates/...`)
> are relative to the skills root — the folder that contains this skill's folder (normally `~/.claude/skills/`).
> Read them from there, whatever the current working directory is. `install.ps1` / `install.sh` put `shared/` there.


Reads certification session artifacts and generates 7 reports: executive summary, functional testing, defect report, traceability matrix, coverage report, production readiness, and the **Test Case Register** (every executed test case with its result). Uses paysec's `/md-to-pdf` (the `pdf` binary) when available; falls back to HTML.

## Inputs

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `session_path` | Yes | — | Path to a `certification-runs/{id}` directory |
| `reports` | No | `all` | Comma-separated list of specific reports: `executive,functional,defects,traceability,coverage,readiness,register` |

## Example Usage

```
/generate-pdf-report session_path=./certification-runs/20260611_142200_myapp
/generate-pdf-report session_path=./certification-runs/20260611_142200_myapp reports=executive,defects
/generate-pdf-report session_path=./certification-runs/20260611_142200_myapp reports=register
```

## Session layouts

| Run type | Where test results live |
|---|---|
| `/application-certification` | `{session}/test-results/**.json` |
| `/migration-certification` | `{session}/old/test-results/**.json` (legacy) and `{session}/new/test-results/**.json` (new) |

Detect the layout first: if `{session}/old/test-results` or `{session}/new/test-results` exists it is a migration run.
Every report that reads test results must read **both** sides for a migration run and label them "Legacy" and "New".

Migration runs also add, in the executive summary and functional testing reports:
- **Completeness** from `comparison/completeness.json` — shown first. If either side is incomplete, the verdict banner reads
  "INCOMPLETE — not certified" and lists every missing item.
- **Roles compared** and a **permission parity table** (Role | Resource | Legacy | New | Gap | Severity) from
  `comparison/behavioral-diff.json → permission_differences[]`.
- **Scope** (legacy and new path prefixes) from `migration-score.json → scope`, so readers know what was and was not certified.

## Preamble

```bash
if [ ! -d "$session_path" ]; then
  echo "ERROR: Session directory not found: $session_path"
  exit 1
fi

SESSION_DIR="$session_path"
REPORTS_DIR="$SESSION_DIR/reports"
mkdir -p "$REPORTS_DIR"

# Resolve paysec md-to-pdf binary (paysec/md-to-pdf/dist/pdf, .exe on Windows)
PDF_BIN="${PAYSEC_PDF_BIN:-}"
for _cand in "$HOME/.claude/skills/paysec/md-to-pdf/dist/pdf" "$USERPROFILE/.claude/skills/paysec/md-to-pdf/dist/pdf"; do
  [ -n "$PDF_BIN" ] && break
  if [ -x "$_cand" ]; then PDF_BIN="$_cand"; elif [ -x "$_cand.exe" ]; then PDF_BIN="$_cand.exe"; fi
done
PDF_AVAILABLE=false
[ -n "$PDF_BIN" ] && PDF_AVAILABLE=true
# Browse binary is also needed for the HTML fallback — resolve it per shared/browse-integration.md

echo "PDF generation: $PDF_AVAILABLE"
echo "Session: $SESSION_DIR"

# Determine which reports to generate
REPORTS_TO_GENERATE="${reports:-all}"
```

## Report Generation Pattern

For reports 1-6, follow this pattern (report 7 is generated by its script, then converted the same way):

1. **Read** required data files from `SESSION_DIR`
2. **Fill** the markdown template (from `templates/`)
3. **Write** populated markdown to `{REPORTS_DIR}/{report-name}.md`
4. **Convert** to PDF via paysec `/md-to-pdf` (if available) → `{REPORTS_DIR}/{report-name}.pdf`
5. **Fallback** to HTML if PDF fails

If PDF generation fails: set status = DONE_WITH_CONCERNS, note which reports are HTML-only.

## Report 1 — Executive Summary

**Data sources:**
- `certification-result.json` (verdict, score, gates)
- `defects/defects.json` (defect counts by severity)
- `coverage/page-coverage.json` ... `api-coverage.json` (all 7 coverage files, including `ui-ux-coverage.json`)
- `paysec_review` section of `certification-result.json` (if --final was used)

Fill `templates/executive-summary.md`. Key sections to populate:
- Verdict banner (PASS / NOT PRODUCTION READY)
- Score: `{score}/100`
- Coverage table: 7 rows with actual percentages and gate status
- Top 5 risks: from `production-readiness-result.json → residual_risks[]` (if exists), else from defects
- Defect summary table: Critical/High/Medium/Low counts
- paysec review summaries (if present)
- Recommendation paragraph

Write to: `{REPORTS_DIR}/executive-summary.md`

## Report 2 — Functional Testing

**Data sources:**
- `test-results/form-tests/*.json`, `test-results/crud-tests/*.json`, `test-results/workflow-tests/*.json`,
  `test-results/ui-ux-tests/*.json`, `test-results/permission-tests/*.json`
- Migration runs: the same folders under `old/` and `new/` (see Session layouts). Produce one set of tables per side.
- Hand-written results (a single `test-results/results.json` with `test_cases[]` of `{test_id, form, type, action, expected, result, evidence}`) are valid too; group them by `form`.

Fill `templates/functional-testing.md`. Key sections:
- Forms tested table: Form Name | Fields | Tests Run | Passed | Failed | Coverage % | Status
- CRUD modules table: Module | Actions Discovered | Tested | Pass | Fail | Status
- Workflows table: Name | Type | Success Path | Failure Path | Status
- UI/UX checks table: Form | checks passed / 9 | failing checks
- Permission summary: Role | resources tested | allowed | denied | violations

For failed tests: include test_id, expected vs actual, and screenshot path.
This report is a **summary**. The complete list of every test case is Report 7 (Test Case Register).

Write to: `{REPORTS_DIR}/functional-testing.md`

## Report 3 — Defect Report

**Data sources:**
- `defects/defects.json`

## Report 7 — Test Case Register (every test case)

**Purpose:** list **every executed test case**, pass or fail, so reviewers can see exactly what was tested, with what
input, what was expected, what happened, and the evidence. Other reports summarise; this one is complete.

**Do not write this report by hand.** It is built by a deterministic script bundled with this skill, so every run lists
100% of the recorded test cases and the output never depends on how the AI summarises:

```bash
# Locate the bundled script (installed copy first, then the framework source folder)
REGISTER_SCRIPT=""
for _cand in "$HOME/.claude/skills/generate-pdf-report/scripts/build-test-register.ts" \
             "$USERPROFILE/.claude/skills/generate-pdf-report/scripts/build-test-register.ts" \
             "./generate-pdf-report/scripts/build-test-register.ts"; do
  [ -f "$_cand" ] && REGISTER_SCRIPT="$_cand" && break
done
[ -z "$REGISTER_SCRIPT" ] && echo "BLOCKED: build-test-register.ts not found — re-run install.ps1" && exit 1

bun "$REGISTER_SCRIPT" "$SESSION_DIR" "$REPORTS_DIR/test-case-register.md"
# exit code 3 = no test results found → report status DONE_WITH_CONCERNS and say so
```

`bun` is always present where paysec is installed. The script:

| Content | Single-app run | Migration run |
|---|---|---|
| Totals by category (form/field, CRUD, workflow, UI/UX, permission, other) | ✅ | ✅ per system |
| Every test case: # · Test ID · target · type · input/action · expected · actual · result · evidence | ✅ grouped by module | ✅ Part B legacy, Part C new |
| Legacy-vs-new comparison | — | ✅ Part A, from `comparison/behavioral-diff.json` (layer 1 scenario parity + layers 2-4). Without that file, tests are paired by ID only when their scenario text matches; the rest are listed as unpaired, never guessed |

Result values: ✅ PASS · ❌ FAIL · ⏭️ SKIPPED (e.g. dry_run) · ℹ️ RECORDED (outcome observed, no expected value given,
typical for permission checks without a role design) · ❔ UNKNOWN (result field missing).
Long cells are truncated to 180 characters; the full record stays in the source JSON.

It accepts the framework's standard result files (form, CRUD, workflow, UI/UX, permission) and hand-written
`results.json` files (`{test_id, form, type, action, expected, result, evidence}`).

Convert it to PDF like the other reports (`test-case-register.pdf`). It can be long (hundreds of rows). That is
intended, which is why it is a separate PDF and not part of the executive summary.

## PDF Conversion

For each generated `.md` file:

```bash
if [ "$PDF_AVAILABLE" = "true" ]; then
  # paysec md-to-pdf: pdf generate <input.md> [output.pdf]
  PAYSEC_BROWSE_BIN="${PAYSEC_BROWSE_BIN:-$BROWSE}" \
    "$PDF_BIN" generate "$REPORTS_DIR/{report}.md" "$REPORTS_DIR/{report}.pdf"

  if [ -f "$REPORTS_DIR/{report}.pdf" ]; then
    echo "PDF created: {report}.pdf"
  else
    echo "PDF failed for {report} — generating HTML fallback"
    generate_html_fallback "$REPORTS_DIR/{report}.md"
  fi
else
  echo "paysec md-to-pdf not available — generating HTML fallback"
  generate_html_fallback "$REPORTS_DIR/{report}.md"
fi
```

If `pdf generate` fails, run `"$PDF_BIN" setup` once — it verifies browse + Chromium and prints what is missing.

### HTML Fallback Generation

```bash
generate_html_fallback() {
  local md_file="$1"
  local html_file="${md_file%.md}.html"
  
  # Convert markdown to HTML using browse JS.
  # paysec browse blocks data: URLs (only http/https/file/about:blank) — use a local file page.
  local render_page="$REPORTS_DIR/.render.html"
  echo '<html><body id=b></body></html>' > "$render_page"
  local render_dir; render_dir="$(cd "$REPORTS_DIR" && (pwd -W 2>/dev/null || pwd))"
  $BROWSE goto "file:///${render_dir#/}/.render.html"
  $BROWSE js "
    const marked_cdn = 'https://cdn.jsdelivr.net/npm/marked/marked.min.js';
    const script = document.createElement('script');
    script.src = marked_cdn;
    document.head.appendChild(script);
  "
  sleep 3
  
  MD_CONTENT=$(cat "$md_file" | python3 -c "import sys,json; print(json.dumps(sys.stdin.read()))")
  HTML=$($BROWSE js "
    (() => {
    document.getElementById('b').innerHTML = marked.parse($MD_CONTENT);
    return '<html><head><style>body{font-family:sans-serif;max-width:900px;margin:40px auto;padding:20px}table{border-collapse:collapse;width:100%}td,th{border:1px solid #ddd;padding:8px}th{background:#f5f5f5}.pass{color:green}.fail{color:red}</style></head><body>' + document.getElementById('b').innerHTML + '</body></html>';
})()")
  echo "$HTML" > "$html_file"
  rm -f "$render_page"
  echo "HTML report: $html_file"
}
```
